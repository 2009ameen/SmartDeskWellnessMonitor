# Smart Desk Wellness Monitor (MVP)

مراقبة الوضعية والمسافة وإجهاد العين محلياً بالكامل (Edge AI). لا صور ولا فيديو على القرص، ولا اتصال شبكي.

## البنية
| الملف | المسؤولية | يعتمد على |
|---|---|---|
| config.py | كل العتبات | - |
| core/metrics.py | حسابات EAR/IPD/الوضعية/الرمش (بلا كاميرا) | config |
| core/calibration.py | معايرة 10 ث بالوسيط + رفض الجودة | metrics |
| core/camera.py | الكاميرا + أخذ عينات تكيفي (5–8 FPS) | cv2 |
| core/detector.py | غلاف MediaPipe FaceMesh+Pose | metrics |
| logic/state_machine.py | تقييم الحالة، عدادات مستقلة لكل مؤشر | metrics |
| logic/alert_manager.py | مستويات 1/2/3 + 20-20-20 + تأجيل مرة | state_machine |
| privacy/audit.py | تدقيق الخصوصية + حارس مقابس Python | - |
| storage/database.py | SQLite أرقام فقط + ملخصات | - |
| main.py | التشغيل والعرض | الكل |

الاتجاه: main → logic → core ← config؛ لا يعتمد core على logic/storage.

## الإصدارات
Python **3.11.x** 64-bit، mediapipe 0.10.14، opencv-contrib-python 4.10.0.84 (لا تثبّت opencv-python معه)، numpy 1.26.4 (mediapipe يتطلب <2)، matplotlib 3.9.2.
اخترنا واجهة `mp.solutions` لأن نماذجها مضمّنة بالحزمة؛ واجهة Tasks الحديثة تحتاج تنزيل ملفات `.task` من الإنترنت.

## التثبيت والتشغيل (PowerShell)
```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1      # إن مُنع: Set-ExecutionPolicy -Scope Process Bypass
python -m pip install --upgrade pip
pip install -r requirements.txt
pip check
python -m unittest discover -s tests -t . -v
python main.py
```
المفاتيح (على نافذة الحالة): `q` خروج، `s` تأجيل 20-20-20 مرة واحدة، `b` تأكيد أخذ الاستراحة.
أخطاء متوقعة: الكاميرا مستخدمة من تطبيق آخر أو إذن الخصوصية مغلق (Settings → Privacy → Camera)؛ رفض المعايرة (إضاءة/كتفان خارج الإطار)؛ `numpy 2.x` (ثبّت 1.26.4).

## حدود مهمة
- IPD بالبكسل مؤشر نسبي وليس سنتيمترات؛ يتأثر بحركة الرأس وزاوية الكاميرا.
- عند 5–8 FPS قد تفوت رمشات سريعة فيُقدَّر المعدل أقل من الواقع. للتجارب العلمية ارفع `target_fps/max_fps` (مثلاً 15) وسجّل ذلك.
- معدل الرمش الابتدائي 15/د قيمة قابلة للتعديل وليست تشخيصاً؛ المخرجات مؤشرات سلوكية تقديرية.
- "الانحراف بالدرجات" هو أكبر انحراف بين: ميل الرأس، ميل الكتفين، زاوية الرقبة، ونزول الرأس نحو الكتفين (الأخير محوَّل بمعامل `vertical_to_deg` تقديري).

## التحقق من الخصوصية (ثلاث مسائل مختلفة)
1. **لا إرسال صور**: الكود لا يكتب إطارات ولا يملك مسار رفع؛ راجع `grep -rn "imwrite\|VideoWriter" .` (يجب ألا تجد شيئاً).
2. **لا اتصالات صادرة من التطبيق**: شغّل `python main.py` ثم افتح *Resource Monitor → Network → TCP Connections* أو **TCPView** وفلتر على python.exe؛ أو **Wireshark** مع فلتر `ip.addr` للعملية؛ أو أنشئ قاعدة صادر Block لـ python.exe في **Windows Defender Firewall** وتأكد أن التطبيق يعمل بلا خطأ.
3. **لا استهلاك شبكي على مستوى الجهاز**: لا يمكن إثباته من التطبيق (الجهاز له عمليات أخرى). قس بـ **Performance Monitor** (Network Interface\Bytes Total/sec) لفترة محددة مع التصريح بحدود القياس.
حارس المقابس داخل التطبيق يغطي Python فقط (connect) ولا يغطي الشيفرة الأصلية؛ لذلك لا يعرض "0 بايت".

## بروتوكول التجربة العلمية
- **العينة**: ≥ 20 مشاركاً (يُفضَّل 30)، تصميم Within-subject (كل شخص مرحلتان).
- **المدة**: 45–60 دقيقة لكل مرحلة، في نفس الوقت من اليوم، بينهما يوم على الأقل؛ بدّل ترتيب المراحل بين المشاركين (Counterbalancing).
- **المرحلة 1 (Before)**: تشغيل التسجيل فقط دون تنبيهات (عطّل AlertManager أو اضبط العتبات عالية جداً) وسجّل المؤشرات.
- **المرحلة 2 (After)**: التنبيهات مفعّلة، نفس المهمة.
- **تثبيت**: الكاميرا والموضع والإضاءة والشاشة والمهمة والكرسي ونفس FPS.
- **المؤشرات**: Healthy Posture %، متوسط الانحراف، متوسط IPD ratio، Blink/min، عدد فترات التحديق، Alert Response Rate (= استجابات `b` أو تصحيح الوضعية خلال 30 ث / عدد التنبيهات).
- **التحسن %** = (After − Before) / Before × 100 (اعكس الإشارة للمؤشرات التي ينخفض فيها الأفضل مثل الانحراف)؛ أضف اختبار Wilcoxon المزدوج وحجم الأثر.
- **مصادر الخطأ**: انخفاض FPS، الإضاءة، النظارات، زاوية الكاميرا، أثر التعلم/الملاحظة (Hawthorne)، اختلاف المعايرة بين الجلسات.
- **تجنب الادعاءات**: لا تذكر "تشخيص" أو "تحسن صحي"؛ قل "تغيّر في مؤشرات سلوكية مقاسة بالكاميرا ضمن عينة محدودة". لا تدرج أرقاماً غير مسجلة فعلياً.
